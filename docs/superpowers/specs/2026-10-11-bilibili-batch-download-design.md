# B 站文件批量下载 — 设计说明

日期：2026-10-11  
范围：`youtube/allInOne.py` 增加「通过文件下载 B 站视频」入口

## 目标

在现有交互式下载器中增加一种模式：从文本文件读取 B 站视频 ID，按统一配置批量依次下载。B 站请求不使用浏览器 cookie。

## 非目标

- 不逐个探测字幕/画质（整批共用一次选择）
- 批量模式不含「字幕当书看」
- 不改 YouTube 单链/播放列表现有流程（仅在入口前加模式选择）
- 不新建独立脚本

## 入口流程

启动 `allInOne.py`（无参数或有参数均可）时，先选择模式：

1. 下载 YouTube（现有流程；若已有 CLI URL 参数则进入后仍用该 URL）
2. 通过文件下载 B 站视频

选 2 后进入 B 站批量分支，不再走 YouTube 链接输入。

## 文件输入与解析

- 提示输入文件路径；回车默认：`{脚本目录}/bilibili.txt`
- 路径相对当前工作目录或绝对路径均可；不存在则报错退出
- 解析规则（同时兼容 JSON 数组与「一行一个 ID」）：
  - 用正则提取 `BV[0-9A-Za-z]+` 与 `av\d+`（大小写按常见写法保留 BV 前缀习惯）
  - 去重且保持首次出现顺序
  - 抽不到任何 ID → 报错退出
- 解析成功后打印数量，并展示前若干条预览

## 配置（问一次，整批共用）

1. **下载类型**：视频 / 仅音频（MP3 或 m4a，复用现有选项语义）  
   - 不含「字幕当书看」
2. **字幕**（仅视频）：复用现有字幕菜单（无 / 内嵌 / 仅字幕 / 单独文件）  
   - 因不逐个探测，字幕语言默认 `en,zh-Hans`（与现有无字幕探测时的默认一致）
3. **画质**（仅视频且非仅字幕）：不探测具体格式，固定提供：  
   - 最佳画质 / 最佳 mp4（优先 mp4）/ 按 `FALLBACK_HEIGHTS` 列出常见分辨率（任意容器）/ 自定义格式串  
   - 确认时打印所选描述

确认摘要后询问是否开始；取消则退出。

## 下载执行

- ID → URL：`https://www.bilibili.com/video/{id}`
- yt-dlp 选项：使用现有 `NO_COOKIE_OPTS`（不加 `--cookies-from-browser`）
- 输出路径：复用现有单视频模板 → `youtube/output/%(title)s [%(id)s].%(ext)s`
- 媒体/字幕/画质参数拼装：复用现有 `download()` 的拼参逻辑；需支持传入「无 cookie」选项集，避免 B 站仍带 Firefox cookie
- 依次下载；单个失败（非 0 退出码或异常）→ 记录 ID 与简要原因，继续下一个
- 全部结束后打印：成功数、失败数、失败 ID 列表

## 与现有代码的关系

| 现有能力 | 批量 B 站用法 |
|---------|---------------|
| `ask` / `ask_choice` | 复用 |
| `build_sub_menu` / 音频选项 | 复用；媒体菜单用无 book 的精简版 |
| `download()` | 复用或抽一层 `ytdlp_opts` 参数 |
| `probe()` | 批量路径不调用 |
| `YTDLP_OPTS` | YouTube 继续用 |
| `NO_COOKIE_OPTS` | B 站批量用 |

## 验收标准

- 菜单可选「通过文件下载 B 站视频」
- 默认可读到 `bilibili.txt`（当前 JSON 数组格式）并抽出全部 BV 号
- 纯文本「一行一个 BV」文件同样可用
- 一次配置后顺序下载；失败不中断整批
- 下载不依赖 Firefox cookie
- YouTube 原流程行为不变

## 实现备注

- 改动集中在 `youtube/allInOne.py`
- 不强制改 `bilibili.txt` 内容
